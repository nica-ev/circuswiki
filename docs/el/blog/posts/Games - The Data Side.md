# **Παιχνίδια - Η Πλευρά των Δεδομένων**
**Πώς οι περιγραφές παιχνιδιών τυποποιήθηκαν και έγιναν πιο δυναμικές χρησιμοποιώντας μεταδεδομένα και πρόσθετα του Obsidian.**

Όταν πρόκειται για τη διαχείριση περιεχομένου, η συνέπεια είναι το κλειδί. Για την πρώτη μεγάλη ενότητα αυτού του έργου, ασχολήθηκα με τα παιχνίδια—περίπου 170 από αυτά, το καθένα με τη δική του μοναδική μορφή, στυλ και προσβασιμότητα. Το πρόβλημα; Πολλές από αυτές τις περιγραφές βασίζονταν σε στατικούς, "σκληρά κωδικοποιημένους" συνδέσμους, καθιστώντας εφιάλτη την προσθήκη νέων παιχνιδιών ή την προσαρμογή της δομής.

Έτσι, έβαλα τα μανίκια μου και έπιασα δουλειά.
<!-- more -->
## Βήμα 1: Μια Ενοποιημένη Μορφή
Το πρώτο μέλημα ήταν να καθιερωθεί μια συνεπής μορφή για όλες τις περιγραφές παιχνιδιών. Άντλησα έμπνευση από το "Tasifan Spielebuch" (Βιβλίο Παιχνιδιών Tasifan), έναν καλά οργανωμένο πόρο για περιγραφές παιχνιδιών. Για να γίνουν τα πράγματα ακόμη πιο φιλικά προς τον χρήστη, πρόσθεσα σύντομες περιλήψεις, ώστε όλες οι απαραίτητες λεπτομέρειες να είναι ορατές με μια ματιά—ακόμη και σε μια προεπισκόπηση.

Αλλά η πραγματική αλλαγή; Τα μεταδεδομένα.

## Βήμα 2: Μαγεία Μεταδεδομένων
Τώρα, όλες οι βασικές πληροφορίες—μέγεθος ομάδας, υλικά, διάρκεια και άλλα—αποθηκεύονται ως μεταδεδομένα στην κορυφή κάθε αρχείου Markdown σε μια μορφή που ονομάζεται YAML (ή frontmatter). Αυτό όχι μόνο διατηρεί τα πράγματα οργανωμένα, αλλά καθιστά επίσης τα δεδομένα επαναχρησιμοποιήσιμα σε όλο το σύστημα.

Για να διευκολυνθεί η εύρεση του σωστού παιχνιδιού, εφάρμοσα μια απλή αλλά αποτελεσματική λογική:
1. **Επιλέξτε μια κατηγορία**: Τι είδους παιχνίδι ψάχνετε; Ένα παιχνίδι χαλάρωσης; Ένα παιχνίδι κυνηγητού; Κάτι για ομαδική εργασία; Έχω δημιουργήσει ένα σύνολο κατηγοριών για αρχή, αλλά αυτές μπορούν να προσαρμοστούν ή να επεκταθούν όπως χρειάζεται.
2. **Περιηγηθείτε στον πίνακα**: Μόλις επιλέξετε μια κατηγορία, θα δείτε έναν πίνακα που παραθέτει όλα τα παιχνίδια που ταιριάζουν. Ο πίνακας είναι ταξινομήσιμος—απλώς κάντε κλικ στις επικεφαλίδες για να οργανώσετε κατά διάρκεια, δυσκολία ή άλλα κριτήρια.

Και εδώ είναι το κόλπο: πολλά παιχνίδια εμφανίζονται σε πολλαπλές κατηγορίες, οπότε δεν περιορίζεστε ποτέ σε έναν μόνο τρόπο εύρεσης αυτού που χρειάζεστε.

## Πίνακες Όχι-Ακριβώς-Δυναμικοί
Η πραγματική μαγεία συμβαίνει με δύο πρόσθετα του Obsidian: **Dataview** και **Dataview Serializer**.

Το Dataview μου επιτρέπει να δημιουργώ δυναμικές λίστες και πίνακες χρησιμοποιώντας ερωτήματα τύπου βάσης δεδομένων. Το πρόβλημα; Αυτοί οι πίνακες λειτουργούν μόνο εντός του Obsidian, επειδή τα υποκείμενα αρχεία Markdown δεν τροποποιούνται.

Εισαγάγετε το Dataview Serializer. Αυτό το πρόσθετο μετατρέπει αυτούς τους δυναμικούς πίνακες σε στατική μορφή Markdown και τους γράφει απευθείας στο αρχείο. Όταν ο ιστότοπος δημιουργείται χρησιμοποιώντας το MkDocs, οι πίνακες είναι στατικοί, αλλά ουσιαστικά δημιουργήθηκαν δυναμικά εκτός σύνδεσης.

Αυτά τα ερωτήματα μπορούν να γίνουν αρκετά περίπλοκα, επιτρέποντάς μου να αναζητώ ή να εμφανίζω συγκεκριμένα μέρη του wiki—όπως όλες τις περιγραφές παιχνιδιών ή άρθρα γραμμένα από συγκεκριμένο συγγραφέα. Και επειδή ενημερώνονται αυτόματα (μέσω του βήματος του serializer), η προσθήκη νέων πληροφοριών και η δημιουργία μιας πλοηγήσιμης δομής είναι παιχνιδάκι.

Αλλά δεν είναι όλα ρόδινα. Η διαδικασία δεν είναι πλήρως αυτόματη. Το Dataview Serializer μπορεί να ξαναγράψει ένα αρχείο μόνο αν είναι ανοιχτό στο Obsidian. Προς το παρόν, αυτό είναι διαχειρίσιμο—έχω επισημάνει κάθε σελίδα με έναν δυναμικό πίνακα ή λίστα, καθιστώντας εύκολη την εναλλαγή μεταξύ τους. Αλλά αν ο αριθμός αυτών των σελίδων αυξηθεί σημαντικά, ίσως χρειαστεί να επανεξετάσω την προσέγγιση.

## Εργαλεία και Γλωσσικά Μοντέλα
Οι αρχικές περιγραφές παιχνιδιών ήταν ένα ετερόκλητο σύνολο όσον αφορά τη μορφοποίηση και την ποιότητα. Για να απλοποιήσω τη διαδικασία, στράφηκα σε γλωσσικά μοντέλα (LLMs). Δημιούργησα μια συγκεκριμένη προτροπή, με παραδείγματα μορφοποίησης, για να διασφαλίσω ότι το ίδιο το περιεχόμενο δεν αλλοιώθηκε (χωρίς περιττές επανεγγραφές). Ωστόσο, έλεγξα χειροκίνητα κάθε αποτέλεσμα και έκανα μικρές προσαρμογές όπου χρειαζόταν.

Το συμπέρασμα είναι το εξής: όταν χρησιμοποιούνται σωστά, αυτά τα εργαλεία είναι *απίστευτα* ισχυρά. Το κλειδί είναι να είστε ακριβείς και σκόπιμοι στον τρόπο που πλαισιώνετε τις εργασίες σας.

Οι τελικές αλλαγές αφορούν κυρίως τη μορφοποίηση—τον τρόπο παρουσίασης των πληροφοριών και των περιγραφών παιχνιδιών. Τα μεταδεδομένα, ωστόσο, εισήχθησαν όλα χειροκίνητα. Δεδομένου ότι έπρεπε ούτως ή άλλως να ελέγξω τα πάντα, η χειροκίνητη εισαγωγή ήταν ταχύτερη σε αυτή την περίπτωση.

Είναι μια αργή διαδικασία, όμως. Δουλεύοντας με μερική απασχόληση, διαχειρίζομαι περίπου 10-15 παιχνίδια την ημέρα. Η πρόοδος είναι σταθερή, αλλά θα πάρει λίγο χρόνο.

## Προκλήσεις Μπροστά
Ένα πιθανό εμπόδιο είναι οι μεταφράσεις. Τα ερωτήματα αναζήτησης θα έπρεπε να προσαρμοστούν για να βρουν εκδόσεις παιχνιδιών ή ετικετών ειδικά για κάθε γλώσσα. Προς το παρόν, αυτό μπορεί να γίνει χειροκίνητα, αλλά αν το σύστημα μεγαλώσει, η αυτοματοποίηση μπορεί να είναι απαραίτητη.

Η μετάφραση είναι ένα σύνθετο θέμα, και θα εμβαθύνω σε αυτό άλλη φορά.

Αυτό το σύστημα έχει σχεδιαστεί για να αναπτύσσεται. Τυποποιώντας τη μορφή, αξιοποιώντας τα μεταδεδομένα και χρησιμοποιώντας δυναμικά εργαλεία, έχω δημιουργήσει μια βάση που μπορεί να διαχειριστεί περισσότερο περιεχόμενο χωρίς να γίνει δυσκίνητη.

## Τι Άλλο Νέο;
Η λειτουργία αναζήτησης έχει λάβει μερικές αναβαθμίσεις:
- **Αυτόματη συμπλήρωση**: Καθώς πληκτρολογείτε, η αναζήτηση προτείνει ερωτήματα που αποδίδουν τα περισσότερα αποτελέσματα. Αυτό δεν βασίζεται στη συμπεριφορά των χρηστών—δεν παρακολουθούμε τις αναζητήσεις—αλλά στον στατικό δείκτη αναζήτησης που δημιουργείται κατά την κατασκευή του ιστότοπου.
- **Αποθηκευμένες αναζητήσεις**: Κάντε κλικ σε ένα μικρό εικονίδιο δίπλα στη γραμμή αναζήτησης και το ερώτημά σας (και τα αποτελέσματα) αποθηκεύονται στη διεύθυνση URL. Σελιδοδείκτη την και θα λαμβάνετε πάντα τα ίδια αποτελέσματα.

Είναι ένα μικρό χαρακτηριστικό, αλλά θα μπορούσε να γίνει απίστευτα χρήσιμο καθώς το wiki μεγαλώνει και καλύπτει πιο ποικίλα θέματα.
