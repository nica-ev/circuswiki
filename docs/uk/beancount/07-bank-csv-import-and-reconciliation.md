# 07 - Імпорт та звірка банківських CSV

Цей робочий процес імпортує нові транзакції Sparkasse до Beancount та підтверджує, що реєстр все ще відповідає реальному банківському рахунку.

## Де відбувається імпорт

| Асоціація | Папка імпорту | Скрипт | Вихідний файл |
| --- | --- | --- | --- |
| NICA | `1. Vereinsverwaltung/Buchhaltung/Buchhaltung-NICA/test` | `csv2bean.py` | `beancount_file.beancount` |
| Tohuwabohu | `1. Vereinsverwaltung/Buchhaltung/Buchhaltung-Tohuwabohu/test` | `csv2bean.py` | `beancount_file.beancount` |

## Перед експортом з Sparkasse

1. Відкрийте правильний файл реєстру.
2. Знайдіть розділ `Balance Checks` (Перевірка балансу).
3. Знайдіть останню дату балансу для рахунку Sparkasse.
4. Також перевірте розділ `Bank Dump` (Банківський дамп) внизу на наявність останньої імпортованої дати.
5. Використовуйте пізнішу з цих дат як точку відліку.

Це допоможе уникнути пропуску транзакцій або подвійного імпорту одного періоду.

## Експорт з Sparkasse

1. Відкрийте огляд рахунку.
2. Відфільтруйте за діапазоном дат.
3. Почніть з останньої перевіреної або імпортованої дати.
4. Закінчіть сьогоднішньою датою або бажаною датою звірки.
5. Експортуйте як `Excel (CSV-CAMT V2)`.
6. Скопіюйте завантажений CSV до відповідної папки `test`.

Скрипти очікують формат Sparkasse CSV-CAMT-V2 із розділеними крапкою з комою стовпцями.

## Конвертація CSV

Відкрийте термінал у відповідній папці `test` та виконайте:

```powershell
python csv2bean.py "NAME-OF-DOWNLOADED-FILE.CSV"
```

Приклад:

```powershell
python csv2bean.py "20260312-1894137139-umsatz.CSV"
```

Якщо все працює, скрипт виведе `Process finished.` (Процес завершено) та створить або перезапише файл `beancount_file.beancount`.

## Що робить конвертер

Конвертер створює базові записи Beancount:

- Вхідні суми за замовчуванням надходять на активний рахунок Sparkasse та `Einnahmen:Sonstiges` (Доходи: Інше).
- Вихідні суми за замовчуванням надходять на `Ausgaben:Sonstiges` (Витрати: Інше) та активний рахунок Sparkasse.
- Деякі описи доходів автоматично класифікуються як `Einnahmen:Vereinsbeitrag` (Доходи: Членські внески).
- Деякі тексти, пов'язані з Tohuwabohu, можуть бути класифіковані як дохідний рахунок проєкту.

Конвертер є лише першим кроком. Він не знає остаточного бухгалтерського значення кожної транзакції.

## Копіювання до основного реєстру

1. Відкрийте `test/beancount_file.beancount`.
2. Пропустіть згенерований заголовок опцій.
3. Скопіюйте лише транзакції.
4. Вставте їх спочатку до основного реєстру, в розділ `Bank Dump`.
5. За потреби додайте роздільник з датою для дати імпорту.

```beancount
****************************************************************************
** 2026-01-13
****************************************************************************
```

`Bank Dump` є проміжною зоною. Імпортовані транзакції пізніше можна перемістити до відповідного тематичного або проєктного розділу.

## Класифікація імпортованих записів

Для кожної імпортованої транзакції вирішіть:

- Це рівень асоціації чи рівень проєкту?
- Це дохід чи витрата?
- Це відшкодування чи погашення зобов'язання?
- Чи належить це до `Freies-Geld` (Вільні кошти) чи до специфічного активного рахунку проєкту?
- Чи є квитанція або рахунок-фактура для додавання?

Замініть загальні резервні рахунки, такі як `Ausgaben:Sonstiges`, якщо існує більш точний рахунок.

## Додавання перевірки балансу

Приклад для NICA:

```beancount
2026-03-13 balance Vermoegen:Bank:Sparkasse-NICA 1234.56 EUR
```

Приклад для Tohuwabohu:

```beancount
2026-03-13 balance Vermoegen:Bank:Sparkasse-Tohuwabohu 2345.67 EUR
```

Використовуйте баланс, показаний Sparkasse на цю точну дату.

## Перевірка у Fava

1. Збережіть файл реєстру.
2. Перезавантажте Fava.
3. Перевірте наявність помилок у верхній частині сторінки Fava.
4. Відкрийте сторінку рахунку Sparkasse.
5. Підтвердьте поточний баланс та останні транзакції.
6. Перевірте Балансовий звіт (Balance Sheet).
7. Перевірте панелі проєктів, якщо були задіяні проєктні рахунки.

## Якщо перевірка балансу не вдалася

Поширені причини:

- У CSV-експорті пропущено один день на початку або в кінці.
- Транзакцію імпортовано двічі.
- Транзакцію вставлено до реєстру неправильної асоціації.
- Число було неправильно відредаговано.
- У проєктному розділенні використано неправильний знак.
- Рухи PayPal або готівки також не були записані.

Не видаляйте перевірку балансу лише для того, щоб зникла помилка. Виправте першопричину розбіжності транзакцій.
